01 / Scope

What the pilot can see

Jamming can degrade or remove a GNSS fix. Spoofing can leave an apparently valid position that is wrong. A coastline shifted against the electronic chart can be a position-input issue while radar still sees echoes. Missing or distorted raw echoes need a separate investigation.

Advisory prototype. Version 1 observes its own antenna and receiver. A quiet monitor does not validate the ship’s position, and a gradual deception can evade detection. The master’s procedures and approved navigation equipment govern the passage. The device is designed to run without internet, SIM, shore service or vessel data feeds. Operation still requires suitable power and a usable antenna installation. Detection coverage varies with the threat and local RF conditions.

One merchant vessel is the initial planning assumption. Any defence trial needs its own approval, installation and data-handling review. This is an independent proposal for evaluation.

03 / Engineering

What we build

CloudGate application and receiver link

Bench-check the exact CloudGate SKU and firmware for SDK deployment, startup, storage, and USB host support for the receiver. Use USB if supported. Otherwise use an electrically compatible serial interface through the appropriate expansion hardware. Use pysbf2 as the bench reference decoder and package a small native SBF reader with the CloudGate SDK if the selected image cannot run Python. Log RFStatus, PVTGeodetic and ReceiverStatus. Check configured message cadence, timestamp samples on arrival and use a monotonic clock for stale-data detection.

On-device web server and UI

The gateway boots into monitoring and serves the UI from its local Ethernet port. A browser on an approved tablet or laptop is only a viewer. Logging continues with no viewer connected. Bundle the page and assets on the gateway and keep LTE, remote management and Wi-Fi disabled for the first trial. Separate read-only status from authenticated export and configuration.

Distinguish possible spoofing, suspected interference, fix unavailable, monitor unavailable and no anomaly detected. Show the reason and data age. Test alert persistence and recovery, boot into monitor unavailable until inputs arrive, and capture crew observations with a single incident button. Keep the first passage silent.

Logging and replay

Record raw SBF messages, host UTC and monotonic timestamps, state transitions, receiver configuration and crew markers. Rotate logs and surface storage failures. Replay the same stream through the same rules. Raw SBF is receiver output. Controlled RF recordings or a simulator are needed to test receiver detection itself.

Later integration

With approval, ingest the position actually displayed on the bridge through an isolated read-only interface and compare it with an independent reference. Start with timestamped coastal radar or visual fixes where available. Define uncertainty, source age and comparison limits before adding an advisory. Offshore coverage needs a separately evaluated reference.

04 / Field procedure

From bench to bridge

  1. Agree scope and owners. Operator sponsors the trial, the master approves onboard activity and stop criteria, a vessel technician owns installation, and an engineer owns logging and recovery. Obtain one sanitised incident summary and distinguish raw radar failure from overlay displacement.
  2. Bench test. Record a clean baseline. Replay fix loss, jumps and slow drift through the application. Check receiver disconnect/reconnect, cold boot after power loss, stale messages, low storage and clock steps. Disconnect the browser and internet throughout a bench run and confirm monitoring and log continuity. Verify that an unavailable monitor cannot appear healthy.
  3. Validate RF detection separately. Use a controlled, shielded lab or conducted simulator. Include benign attenuation and multipath-like conditions, jamming, sudden deception and gradual drift. Record simulator truth and exact firmware/configuration. No over-the-air interference during the vessel trial.
  4. Install alongside. Use the approved clear-sky antenna site, secured cable route and dry indoor position. Check approved power, receiver diagnostics, spare cable, log space and clock alignment. Confirm the status page opens from the isolated local Ethernet connection. Keep the device offline and isolated from bridge systems.
  5. Run one silent passage. The watch follows normal procedures. When workload allows, record the time and observation, affected displays, any independent fix and its uncertainty. Suspend the trial if the mount, cable, power or equipment creates a hazard or distracts the watch.
  6. Debrief and decide. Match crew markers and independently timed observations to receiver logs. Export only the operator-approved dataset. Remove the kit or agree a follow-on trial and apply the agreed retention policy.

05 / Pilot intake

What we need to start

One vessel, one normal passage, and one watch officer for a short debrief. Confirm the antenna mounting point, cable run, indoor position, power, installation owner, available reference fixes and whether logs can be retained or exported. Keep vessel identifiers, tracks and raw incident files off this public brief.

Before boarding

Sign off on safe temporary installation, no bridge-system integration, offline operation, and demonstrated detection of missing or stale inputs on the bench. Agree permitted log contents, access, retention and deletion before capture.

Measure with a known reference

Track time to advisory, position error at advisory, missed events by scenario, nuisance alerts per watch, and logging coverage. Mark position error as unknown when a usable reference is absent. Agree acceptable thresholds with the operator for the intended waters before evaluating results.

Gate for a visible advisory

Review the lab results and passage data with the master and operator. A quiet passage establishes a baseline. A visible advisory needs evidence against the agreed scenarios and a reviewed crew response. Operational integration requires a separate approval path.
